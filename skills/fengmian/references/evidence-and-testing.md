# Evidence and optional testing

Source review date: 2026-10-29. Use this reference when explaining the design basis, evaluating claims about performance, or responding to a request for testing.

## Evidence boundaries

The current guidance combines YouTube's creator documentation with qualitative observations of a small, purposively selected set of AI-video thumbnails. The sample is not representative, a quality ranking, or a controlled experiment. Creator analytics and causal thumbnail-performance data were not available.

Recurring design mechanisms worth testing include a recognizable promise, useful outcome imagery, clear visual hierarchy, image/title complementarity, and legibility at small sizes. These are transferable principles. A specific color, facial expression, layout, or prop is a contingent style choice.

Apply the mechanism to the user's content and audience. Horizontal YouTube thumbnails do not establish effects for portrait feeds, Douyin covers, or other placements. Current user choices and approved local revisions remain binding.

## Lightweight feedback loop

Use only when useful to the requested work; do not turn routine cover creation into a mandatory analytics project.

1. Define the question and a testable hypothesis, such as whether enlarging the actual output makes the promise easier to recognize.
2. Prepare only the variants the user requested. Make their conceptual differences meaningful. If several features change together, assess the whole treatment; do not attribute a result to one feature alone.
3. When isolating a thumbnail change, keep the title and content stable where practical. If both title and image change, interpret the result as a package comparison.
4. Prefer an authorized concurrent platform test when available. Sequential swaps and cross-video comparisons have additional timing, audience, and distribution confounds.
5. Record the platform's conclusion and available audience/watch data. A result may be inconclusive. Do not select a winner from a small CTR difference without relevant exposure and context.

Do not publish, replace a live thumbnail, start monitoring, or generate additional variants without scope for that action. Recheck current platform capabilities when an actual test is requested.

## Compact record

Add to the normal revision note only fields supported by the task:

- Selected promise and hypothesis
- Candidate paths and meaningful differences
- Publishing title and viewing surface
- User-provided publication/test dates and comparison conditions
- Available impressions, CTR, watch data, and source
- Platform result, missing information, and practical next decision

Missing data remains missing. Never invent CTR, test duration, statistical significance, viewer recognition times, or improvement percentages. Use the evidence to update the relevant design choice; avoid turning one winning campaign into a permanent template.
